Source-only Auth parameterization of the published 4da7 generic owner.

The six backend files remain unchanged and must match their byte pins. The
launcher redirects only its coordinator target and anchors backend paths. The
owner redirects only the proof workload target, passing the unchanged backend
and the sealed Auth policy source. Existing OwnedUnits allocation, admission,
expiry, private daemon/proxy, recovery and physical cleanup are retained.

prepare_launcher.py only renders a launcher. It does not start it. A separately
authorized Linux no-SDK qualification would invoke that rendered launcher with
Lane auth and Stage proof, then auth_proof.py with role readback, the same backend,
policy and evidence paths. No workflow dispatch or native execution is authorized
by this source packet.

The Auth policy is tested against the actual pinned pure create_plan function.
Windows controls extract that function and OWNER assignment from the pinned AST;
they do not load a Unix socket server or claim Windows runtime compatibility.
The synthetic PostgreSQL model and the existing generic empty-image lifecycle
workload remain separate evidence. The latter cannot prove PostgreSQL startup.

Real Testcontainers create wire, its assembly/source identity, effective kernel
caps and PostgreSQL/customer behavior have not been captured or validated. The
model explicitly reports these runtime claims false. The customer intake stays
disabled before SDK allocation. Runtime acceptance requires that wire binding
and separately qualified admission, followed by the required regression suite.
