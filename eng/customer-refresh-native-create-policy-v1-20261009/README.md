# Auth fixture pre-birth policy adapter

This source-only adapter supplies the missing PostgreSQL-create policy without editing the frozen five-file customer packet or creating another owner framework. It allocates nothing, opens no Docker socket, and launches no worker. It requires an existing qualified private-daemon owner to supply its actual run, finite lease, cgroup and independently inspected immutable image/volume declaration before create. Environment/body values are returned to that private API hook and must never enter custody reports.

The policy replaces a mutable fixture image tag with the inspected image ID, injects Auth ownership and finite-expiry labels, enforces memory/CPU/PID limits and the owned cgroup before birth, restricts dynamic forwarding to loopback, and covers the inspected PostgreSQL data volume with tmpfs. MemorySwap equals Memory; actual owner readback must verify both and the effective cgroup swap limit. Persistent mounts, privileged/host networking, caller ownership claims, workload/health command overrides and unsupported capabilities fail closed. It leaves cleanup observation possible by disabling auto-removal. Actual Testcontainers default command/health serialization has not been captured; incompatible defaults are rejected until separately reviewed, never silently allowed.

This is not yet connected to a qualified owner. The inspected Intranet employee owner hardcodes another workload/label, two containers and fixed phase observation; its `execute` cannot serve as Auth acceptance. Root must identify or qualify the existing generic owner hook and lifetime/fixture caps, then connect this policy to actual create admission and physical cleanup proof. No provider compatibility, Docker wire interop, native SQL or customer C# execution is claimed. The transport's native refusal remains in force.
