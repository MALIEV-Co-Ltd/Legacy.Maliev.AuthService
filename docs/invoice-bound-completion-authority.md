# Invoice-bound completion authority

Originalc821605b7ecde5f79d01966888b116defb10650d restores employee-origin late attachment of an invoice to an already accepted quotation. Current Accounting commits financial rows before the existing Quotation decision can reject its nonemployee origin. This Auth slice supplies the bounded signing boundary; Accounting's early immutable receipt, two-phase prepare/resume flow, Quotation's exact proof verifier and Intranet's fresh credential handoff are separate coordinated implementations. None is inferred from this Auth fixture.

The existing quotation-invoice-completion request gains optional positive InvoiceId. Omission preserves the old quotation/operation capability and does not invoke financial readback. A bound request preserves current Intranet workload admission, genuine employee token/session/store/stamp/family checks, current accounting-create and quotation-update grants, uncached employee IAM, and final post-await expiry/session checks. It also requires two matching authenticated financial readbacks around IAM. No binding or source version is accepted from the caller.

Fixed GET /internal/invoice-creation/operations/{operationId:guid}/financial-ownership uses Services:AccountingService:BaseUrl and Auth's own signed service:legacy-auth workload with the exact legacy.accounting.invoice-financial-ownership.read grant. It is isolated from general permission transport: HTTPS origin validation, no redirect/retry/resilience, ten-second deadline and at most32KiB. Missing grant/configuration, malformed/unavailable readback and changed financial proof cannot mint. Accounting404/409 are distinct denial. The exact nine-field version-one response is:

- ContractVersion: integer1.
- OperationId: canonical lowercase D UUID, matching the requested operation.
- QuotationId and InvoiceId: positive integers.
- OriginIssuer: the configured Auth issuer.
- EmployeeSubject: the current genuine employee subject.
- RequesterSubject: service:legacy-intranet.
- OriginalQuotationVersion: canonical UTC DateTime O with seven fractional digits and endingZ; alternate +00:00 spelling is rejected.
- FinancialBinding: uppercase64 SHA256 from Accounting's immutable admission plus actual committed Invoice/items receipt.

All fields are mandatory; duplicate, unknown or mistyped fields and other versions are unavailable. Actual Accounting currently preserves PascalCase in its normal Program JSON options; the joined lane must still verify its produced wire shape and independently persisted financial ownership. Historical null-issuer or uncertain admissions and adoption by invoice number alone are not proof.

The actual signer reuses the existing capability family: audience legacy-quotation:invoice-complete, scope legacy.quotation.invoice-complete, azp service:legacy-intranet, executor service:legacy-accounting, employee subject, quotation/operation UUID and at most120 seconds bounded by the current employee token/session. Bound proofs additionally contain exactly invoice_id, quotation_version, financial_binding and financial_binding_version=invoice-creation-financial-v1. They contain no role, ordinary actor permissions, employee credential, stamp, email or refresh credential. Quotation must reject old invoice-unbound proofs for invoice attachment and independently verify exact fields, workload executor, lifetime, live authorization and financial/version binding. Accounting does not become a generally trusted employee caller.

The early receipt must commit with Invoice/items/admission independently of notification activation. Existing FinancialResultJson requires a stored file and is saved after Quotation completion, so it is insufficient for the early proof. Intranet must obtain fresh current employee authority after financial preparation and explicitly resume the same operation with a newly minted proof. Expired proof is not renewal authority; no employee JWT is persisted, no service-only remint is introduced and no old null-issuer row is promoted. Same-key recovery requires exact authenticated financial/decision readback rather than repeating side effects or changing versions silently.

Thirty-four new Auth controls use normal Production Program, real isolated PostgreSQL identities/sessions, actual credential/workload/token issuers and live transport composition. The external Accounting HTTP boundary is controlled metadata, not an actual Accounting database witness. Cases cover bound/unbound positive contracts, foreign issuer/actor/IDs, malformed/ambiguous/oversized/versioned metadata, missing own workload grant, denial versus transport failure, genuine customer/service/scoped credentials, signer rejection and stamp/revocation/financial changes during the second read. Whole mapped identities, session rows and actions remain unchanged by mint/rejection. Existing capability negatives and actor/creation delegation boundaries remain intact. The independent joined lane must prove the actual financial receipt, prepared/resumed operation, Quotation/Order/history and acknowledgement-loss reconciliation.
