# Read-only identity lockout deadline

Part of a combined source policy draft on Auth148 merged main2d01cd55a27526a23291793a115fdd490e04cf0e; fresh main37410437049 accepted all780 cases; this new bundle native validation remains pending.

Original Identity8.0.3 UserManager.IsLockedOutAsync treats a configured enabled lockout end equal to the current UTC instant as locked: https://raw.githubusercontent.com/dotnet/aspnetcore/v8.0.3/src/Identity/Extensions.Core/src/UserManager.cs (lines1587..1597). Accepted interactive login146 and customer confirmation145 already implement that inclusive deadline. The read-only LegacyIdentityReader instead permitted equality through <= and CustomerSelfIdentityReader through >. This draft changes only those comparisons to < and >= respectively.

Direct credential verification, active refresh lookup, Google employee lookup and customer self contact lookup remain read-only. No counter/hash/stamp changes are introduced. Missing/unconfirmed state and disabled/null lockout behavior retain their existing rules. This does not promise a read/write fence across later session issuance or restore the original Google provider or full framework sign-in semantics.

Four normal Production HTTP/PostgreSQL controls use a frozen clock at PostgreSQL timestamp precision. Customer/employee cases require exact-deadline direct validation and active lookup denial, actual refresh401 with normal family rotation/revocation, expired-by-one-microsecond reads and refresh200, disabled-lockout reads, and unchanged complete identity snapshots. Customer self requires403 at equality, then200 after expiry or disabled lockout with the exact safe customerId/email/mobile shape and all identity/receipt/effect/action/session rows unchanged. Google uses the existing controlled external credential validator only: real service authentication, nonce endpoint/store/consumption, normal reader and session/issuer enforce403 at equality with no session, reject consumed nonce401, then expired/disabled exchange200 with unchanged identity rows. Google nonce/session changes are expected; no guaranteed session rollback is claimed.

Release0W/E, full/raw and all prior foci, six generated sources, six offline EF commands and static/privacy checks remain required.
