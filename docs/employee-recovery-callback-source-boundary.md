# Exact employee recovery callback token boundary

Source `5e2030b7339d4d9bd699fd8c3f406b71706b377d`, parent `1498292f1653a7c7c07f5c6f6e89139925684f5c`, adds `Maliev.Identities.IdentityEmailTokenCodec.cs` blob `dbeb587e9316c94f2838cd3cb3ce38d59d9c7a38`. Its source Intranet callers encode ASP.NET Identity tokens and try ordered decoded/raw/percent/space-to-plus candidates before Identity validation.

Current Auth instead issues a 32-byte random Base64URL challenge and binds its exact hash to stamp, owner, email and purpose, with one-use recovery receipts. Current Intranet callback construction uses QueryHelpers.AddQueryString and sends the bound opaque token to Auth. Its existing BFF test preserves an opaque `+/=&?` token and an email containing plus through a URL roundtrip. These contracts do not establish acceptance of old Identity links or their data-protection authority.

Two new normal Production Auth Program HTTP cases cover password reset and email confirmation with actual disposable PostgreSQL stores, actual configured Intranet service-login issuer, normal IAM/workload exchange and recovery services. Controlled primary transport loops Auth's workload exchange to its own normal service-login endpoint and supplies IAM grant decisions. Permission configuration belongs only to the synthetic test fixture. No authentication/provider/session/recovery/IAM service replacement is made.

Each case obtains a fresh actual challenge, roundtrips it and its plus-containing email through QueryHelpers, rejects seven altered body token representations (percent, double percent, Base64URL wrapping, plus suffix, space suffix, malformed percent and incomplete percent), and compares complete identity/action snapshots after every rejection. No recovery effect appears. The original token then completes, the action is consumed and receipt acknowledged, and replay denies. Normal IAM/workload requests must be observed and unmatched external requests refused.

This is a boundary validation slice, with no production runtime or dependency pin changes. It neither copies the unused codec nor adds decoder fallback to current tokens. The actual compiled Intranet-to-Auth application join is separate; framework QueryHelpers roundtrip plus normal Auth HTTP is not that binary join. Original Identity-token compatibility remains a separate migration contract gap; no whole source/path closure is claimed.

Validation is hosted-first: build with zero warnings/errors, focused two-case run, existing relevant/full suite, generated-inclusive raw owned coverage, formatting/audit/security/evidence controls. No knowingly broken tests-only RED commit or local SDK/Docker run. Candidate/main acceptance must be recorded from fresh actual runs, not inferred from this document.
