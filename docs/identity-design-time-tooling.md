# Offline PostgreSQL identity tooling

The original employee/customer builders implement `IDesignTimeDbContextFactory`, rather than choosing the runtime provider. Their five-version, ten-path historical source cohort remains distinct from database/data migration acceptance. Current Auth uses PostgreSQL registrations in the API host; only the refresh-session context has an explicit factory. Missing identity factory classes do not alone prove an EF CLI failure.

`eng/Test-IdentityDesignTime.ps1` exercises the actual EF 10.0.12 CLI using the already-built Release Infrastructure project and API startup project. Customer and employee contexts use normal host discovery; refresh sessions provide the existing factory control. It runs `dbcontext info --json` and `migrations script --idempotent` separately for each exact context. It asserts the PostgreSQL provider, context type, synthetic database/endpoint, successful exits, and nonempty generated SQL. It never runs `database update`, scaffold, a database connection check, or generated SQL.

Run the probe only after the normal hosted Release build with both pinned local dependencies present. Hosted CI installs the exact matching tool into a temporary directory. Child processes receive an allowlist of runtime paths and synthetic configuration: Production, ephemeral RSA, disabled recovery, and loopback port 1 for normal host identity registration. The existing refresh factory retains its own `localhost:5432` / `legacy_auth_design` design-only metadata; offline commands do not open that connection. Inherited application configuration and credentials are omitted. No private key, raw CLI output, or generated SQL is retained. Each command has a 60-second deadline. The receipt retains only allowlisted command results and SQL size/hash.

The actual CLI outcome determines whether host fallback is sufficient. The private startup boundary may affect EF host-abort handling; this is a hypothesis pending hosted measurement. There is no runtime factory or startup behavior change in this probe. The existing two PostgreSQL migration tests separately prove schema creation, not this CLI lifecycle or original live data. No historical source closure or tool success is claimed before the hosted receipt is inspected.

EF context creation and command semantics are documented in [Microsoft's design-time guide](https://learn.microsoft.com/ef/core/miscellaneous/cli/dbcontext-creation) and [CLI reference](https://learn.microsoft.com/ef/core/cli/dotnet).
